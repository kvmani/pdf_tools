PDF TOOLS / HELP & GUIDE

Page transformation, made auditable

PDF Tools works with any PDF — reports, scans, forms, presentations, invoices, manuscripts, or drawings. It validates each document, reads its page tree, applies an explicit one-based selection and order, then writes a new document. Your file is processed on this office intranet server and is never stored or sent anywhere.

YOUR DOCUMENTS, YOUR NETWORK

Privacy and data security

  • Any PDF is welcome. Official, administrative, personal, or technical — there is no restriction on the subject of your document, and the tool never inspects or interprets its content.
  • Nothing is stored. Uploads are held only in server memory for the lifetime of your request and are released as soon as the result is returned.
  • Nothing leaves the office network. The service runs entirely on intranet hardware. No document, page, or fragment is transmitted to the public internet or to any third-party service.
  • No personal information is collected. The tool does not identify you, build a profile, or record what you worked on.

Algorithm

  1. Confirm the PDF signature, encryption state, size, and readable page tree.
  2. Parse inclusive one-based ranges such as 1-3, 6.
  3. Preserve the user's file and range order.
  4. Copy selected page objects into a new page tree.
  5. Stream the result, then release request memory.
\[ P_{\text{out}} \;=\; \big\Vert_{\,j=1}^{\,m}\; P_{j}\bigl[a_{j} : b_{j}\bigr] \]

The output is the ordered concatenation of every selected range, where \(P_{j}\) is the page list of document \(j\) and \(a_{j}, b_{j}\) are the first and last page of a selected one-based range.

\[ N_{\text{out}} \;=\; \sum_{j=1}^{m}\,\bigl(b_{j}-a_{j}+1\bigr) \]

Every range is inclusive, so a 1-3 selection contributes three pages.

Critical inputs

Source PDF
Any PDF, regardless of subject. Determines the available pages, metadata, encryption state, and processing cost.
Page range
Controls exact inclusive selection; missing pages are rejected.
Document order
Controls concatenation sequence in a merge.
Export mode
PDF preserves page objects; image export rasterizes them.
\[ S_{\mathrm{MiB}} \;=\; \frac{S_{\text{bytes}}}{2^{20}} \]

Upload size is reported in binary mebibytes so the operational limit is unambiguous.

Limits and failure modes

  • Reordering does not edit page content or repair damaged PDFs.
  • Locked and malformed files are rejected with safe messages.
  • Raster export loses vector text and should be used only when needed.
  • Processing is local and request-scoped; deployers must still configure proxy upload limits.
